# Current state

## Versions

Version 0.1 is the approved, stable baseline. It provides a responsive Leaflet/OpenStreetMap page, an automatic one-time browser location request with a high-accuracy attempt and fallback, a marker, an accuracy circle, coordinates, browser accuracy, a quality label, and clear error messages. Mobile HTTPS testing was validated through a tunnel.

Version 0.2 is the approved and validated stable baseline. It replaces the one-time request with `watchPosition()` so the displayed location can update without reloading. Tracking starts automatically when the page loads, with no manual Start/Stop controls. Each update moves the existing marker and accuracy circle and refreshes the coordinates, accuracy, and quality label. Dragging the map pauses automatic centering while location updates continue; reloading resumes following. The map uses OpenStreetMap's documented tile URL and recalculates its size when the map container changes.

Version 0.3 is the approved and validated named-location and `localStorage` baseline. It retains the responsive Leaflet/OpenStreetMap map, automatic continuous tracking, live marker and accuracy-circle updates, coordinates, browser accuracy, quality classification, and HTTPS mobile compatibility. After a valid position is received, Save Location captures a frozen latitude, longitude, accuracy, and timestamp. A native naming dialog saves the snapshot to the `locationMap.savedLocations` array in this browser's `localStorage`. A visible Saved locations counter reads that array on page load and updates after each successful save. Live tracking continues while the dialog is open. Version 0.3 has been deployed and tested through GitHub Pages. No saved-location list, CSV export, backend, or database is included.

Version 0.4 is the approved and validated stable baseline. Export CSV downloads every saved record as a CSV generated entirely in the browser from `locationMap.savedLocations`, with properly escaped `name`, `latitude`, `longitude`, `accuracy`, and `timestamp` columns. The filename is `saved-locations-YYYY-MM-DD-HHMMSS.csv`, using the device/browser local date and time, a 24-hour clock, and zero-padded values without colons, slashes, or spaces. Batches exported at different seconds on the same day have distinguishable filenames; stored record timestamps remain unchanged. Once the download is initiated, the app writes `[]` to that key, resets the Saved locations counter to zero, and disables Export CSV until a new location is saved. Each downloaded file archives one batch. Malformed or empty stored data disables export; failed CSV preparation or download initiation leaves saved records untouched. No saved-location list, CSV import, backend, or database is included.

Version 0.5 is the approved and validated stable baseline on Version 0.4. It automatically reads only the root `locations.csv`, using the existing `name,latitude,longitude,accuracy,timestamp` format and a plain JavaScript parser for quoted fields, commas, doubled quotes, and line breaks. Rows with invalid latitude or longitude are skipped without stopping valid rows. Each valid CSV location becomes a separate Leaflet marker with a permanently visible name label; CSV markers remain separate from the live GPS marker. The CSV locations counter shows the number of displayed markers, and the map fits their bounds once after loading. Clear Map removes only CSV markers and labels, resets the CSV counter, and leaves the file, `localStorage`, and live GPS tracking untouched. Refresh reloads the unchanged CSV file and restores its valid markers. The app reads the file but never writes to it.

Version 0.6 is the approved and validated current stable baseline on Version 0.5. Tapping a CSV marker requests a walking route from the latest valid live GPS position to that marker through the openrouteservice Directions API at `api.heigit.org`, using the `foot-walking` profile. A separate Leaflet route layer draws the GeoJSON route polyline, and the page shows the destination name, walking distance, and approximate walking time. Only one route is active; selecting another marker replaces it. Clear Route removes the route and its information, while Clear Map also removes any active route when CSV markers are cleared. Live GPS continues updating while the route remains static. There is no automatic rerouting or turn-by-turn navigation. The testing API key remains local in `js/config.js`, which is excluded from Git by `.gitignore`; it is not committed or pushed to GitHub. Public routing deployment is deferred until a safe API-key protection method is selected.

## Testing and access

Run `npx http-server . -p 8000 -c-1` from the project directory for local development. `http://localhost:8000` supports desktop geolocation on the same computer. A phone can view the layout over the computer's HTTP LAN address, but phone geolocation needs an HTTPS URL. Versions 0.2 through 0.5 were deployed and tested through GitHub Pages. Version 0.6 routing was validated through a local HTTPS Cloudflare Tunnel (`cloudflared tunnel --url http://localhost:8000`). GitHub Pages may host non-routing project files, but routing is not publicly deployed with its API key.

The browser reports the accuracy value; the application cannot make it more precise. Desktop estimates may be coarse. `watchPosition()` updates are controlled by the browser and device, not a fixed timer. Before export, saved locations remain local to the browser and device and may be removed when site data is cleared. Browser download initiation cannot guarantee permanent retention of an exported file.

Version 0.2 was checked with JavaScript syntax validation, simulated watch callbacks for automatic startup, fallback, errors, marker and circle reuse, and accuracy ranges. A narrow browser render confirmed the map still fits the screen. GitHub Pages HTTPS mobile testing is recorded as validated for this approved baseline.

Version 0.3 was checked with simulated GPS updates and browser storage for snapshot freezing, name validation, multiple saves, persistence after reload, malformed stored JSON, Cancel, and the existing tracking fallback. A phone-width browser render confirmed the dialog fits. Desktop browser testing and iPhone HTTPS testing passed on the deployed GitHub Pages site, including continuous geolocation, Save Location, frozen snapshots, localStorage persistence, and the Saved locations counter after reload. Version 0.3 remains the approved and validated named-location baseline.

Version 0.4 adds an export-and-clear cycle on top of Version 0.3. Laptop/browser and iPhone HTTPS testing passed through the deployed GitHub Pages site. Tests confirmed saved `localStorage` records, correct CSV contents, distinguishable local date-and-time filenames, reset of `locationMap.savedLocations` to `[]`, counter reset to zero, Export CSV disabling after clearing, and a new collection cycle after another save. Version 0.4 remains the approved and validated stable baseline.

Version 0.5's root `locations.csv` now contains saved location records. Local simulated checks covered missing, empty, header-only, valid, and partly invalid CSV files; quoted names; marker labels; one-time fitting; GPS updates; Clear Map; refresh; and Version 0.4 export compatibility. Laptop/browser and iPhone HTTPS testing passed on the deployed GitHub Pages site. Testing confirmed automatic CSV loading, labeled markers, the CSV counter, fitting to imported markers, clearing only CSV markers, restoring them after refresh, and continued live GPS tracking. Version 0.5 remains the approved and validated stable baseline.

Version 0.6 passed local JavaScript syntax and simulated routing checks for the `api.heigit.org` POST request, longitude/latitude coordinate order, success and error responses, route replacement, cancellation, Clear Route, Clear Map, continued GPS updates, and Version 0.5 save/export behavior. Laptop/browser and iPhone/mobile tests through a local HTTPS Cloudflare Tunnel also passed. They confirmed CSV markers, route calculation from live GPS to the selected marker, route drawing, destination name, walking distance, approximate walking time, replacement when another marker is selected, Clear Route, and continued live GPS updates while the route stays static. Version 0.6 is approved and validated as the current stable baseline. Its API key remains in locally served, Git-ignored `js/config.js`; the key is not uploaded to GitHub and routing is not publicly deployed with it. The client-side key can be read by anyone with access to the local test URL. Routing requires network access and openrouteservice availability and quota. No backend, database, protected API proxy, automatic rerouting, turn-by-turn navigation, or route history is included.

See `README.md` for features, testing steps, accuracy thresholds, known limitations, and version history.
